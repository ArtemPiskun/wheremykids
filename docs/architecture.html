«Де мої діти»: семейный локатор для Украины

Документ отвечает на 20 пунктов задания: рынок, состав MVP, стек, архитектура, схема данных, API, алгоритм фоновой геолокации, безопасность и право, монетизация и план работ. Решения приняты так, чтобы MVP вырос в production без переписывания.

Принцип продукта. Детское приложение работает ненавязчиво (не мешает, не тратит батарею, не требует внимания), но не скрыто: ребёнок видит, кто видит его геопозицию, ОС показывает индикатор геолокации, а в онбординге есть понятный экран согласия. Это требование и закона, и магазинов приложений, и основа доверия к бренду.

02Ключевые функции MVP

Родитель — Must have (MVP 1.0)

  • Регистрация (email + пароль), вход, выход, удаление аккаунта
  • Создание семьи, второй родитель по приглашению
  • Добавление нескольких детей (имя, аватар, год рождения)
  • Приглашение ребёнка по QR или 8-значному коду
  • Карта с детьми: аватар, имя, время обновления
  • Статусы: онлайн / недавно / нет связи, батарея
  • История и маршрут за выбранный период
  • Геозоны (Дом, Школа, Спортзал, Другое), вход/выход
  • Push, SOS-тревога, звонок ребёнку
  • Устройства: список, отзыв; экспорт данных

Ребёнок — Must have

  • Подключение по QR/коду (без пароля)
  • Экран согласия и объяснение, что видят родители
  • Фоновая геолокация с адаптивной частотой
  • Offline-очередь и досылка
  • Статус соединения, список подключённых родителей
  • SOS с защитой от случайного нажатия
  • «Отправить моё местоположение» сейчас
  • Пауза передачи (по возрастным правилам) и выход из семьи

Отложено в 1.1–2.0

  • Вход по телефону + OTP (TurboSMS / AlphaSMS)
  • Режим «Повітряна тривога» и «Я в укритті»
  • Полигональные геозоны, расписания зон
  • Приватный режим с E2E-шифрованием
  • GPS-часы, Apple Watch / Wear OS
  • Детекция ДТП, отчёты по неделе

Сознательно не делаем: прослушку окружения, чтение переписок, скрытый режим без иконки. Это отрезает спорную аудиторию, но защищает от блокировки в сторах и от юридических рисков.

Решение: Flutter. Фоновая геолокация — это примерно 5% кода, и она изолирована за интерфейсом LocationEngine. В MVP он реализован на geolocator (foreground service на Android, background location на iOS) с собственным адаптивным алгоритмом на Dart. На этапе 1.1 тот же интерфейс получает нативную реализацию на Kotlin (FusedLocationProvider + Activity Recognition + Geofencing API) и Swift (CLLocationManager + significant-change + region monitoring). Один код, две сборки (flavors): «Де мої діти» для родителей и «Де мої діти: Дитина» для ребёнка. Так приложение родителя не запрашивает фоновую геолокацию, а это упрощает ревью в Google Play и App Store. Детское приложение маленькое и легко объясняет свои разрешения.

Поток местоположения

  1. Ребёнок: LocationEngine выдаёт отфильтрованные точки, они пишутся в локальную SQLite-очередь.
  2. SyncService пачками (до 100 точек) отправляет их в POST /v1/locations/batch с идемпотентными clientId.
  3. API валидирует, шифрует координаты (AES-256-GCM), пишет в партицию locations одним INSERT и обновляет last location в Redis, если точка новее.
  4. Геозоны оцениваются синхронно для самой свежей точки (круги, гистерезис) и при переходе создают событие и push.
  5. Событие location.updated публикуется в комнату семьи. Через Redis adapter его получают все pod-ы, а затем родители, подключённые по WebSocket.

Масштабирование до сотен тысяч пользователей

Оценка: 300 тыс. активных детских устройств. Средний интервал отправки с учётом стационарности около 4 минут, это ~1 250 точек/с, но они приходят пачками, поэтому выходит ~150–250 запросов/с. Это нагрузка для 3–4 pod-ов API и одного primary PostgreSQL с батч-вставками. Узкие места и их решения:

  • Запись истории: месячные партиции, только BRIN/B-tree (child_id, recorded_at), удаление старых данных через DROP PARTITION вместо DELETE. Следующий шаг — Redis Streams/Kafka как буфер ingest и отдельный сервис записи.
  • WebSocket: ~50 тыс. соединений на pod (Node + uWS при необходимости). Redis adapter, комнаты по семье.
  • Чтение: карта читает только Redis (last location), историю читают редко и по индексу.
  • Шардирование по family_id понадобится только после ~5 млн устройств.

06Database schema

08WebSocket-события

Socket.IO namespace /rt, только websocket-транспорт. Access JWT передаётся в auth.token при handshake. 09Алгоритм фоновой геолокации

Цель: точность маршрута, когда ребёнок движется, почти нулевой расход, когда он стоит, и никаких потерь при обрыве связи. Координаты не отправляются каждую секунду. Устройство работает как конечный автомат, а частота зависит от состояния движения и батареи.

stateDiagram-v2
  [*] --> Stationary
  Stationary --> Moving: выход из стоп-зоны 120 м / activity != still / скорость > 1 м/с
  Moving --> Stationary: все точки в радиусе 40 м в течение 3 мин
  Moving --> Vehicle: медиана скорости > 7 м/с (25 км/ч)
  Vehicle --> Moving: медиана скорости < 4 м/с 60 с
  Stationary --> Burst: SOS или запрос родителя
  Moving --> Burst: SOS или запрос родителя
  Burst --> Moving: через 15 мин или отмена SOS

Модификаторы батареи

  • Зарядка: интервалы ×0,5 (можно чаще).
  • Заряд < 30%: интервалы ×2, точность не выше balanced.
  • Заряд < 15% («режим блэкаута»): Moving ведёт себя как Stationary с heartbeat 10 мин. SOS работает всегда.
  • Android Power Saver / iOS Low Power Mode: как < 30%.

Фильтрация шума

  1. Отбрасываем точки с accuracy > 150 м. Если других точек нет больше 10 минут, принимаем лучшую с флагом coarse: родителю важнее «примерно здесь», чем пустота.
  2. Отбрасываем «телепорты»: скорость относительно последней принятой точки > 70 м/с (252 км/ч) при плохой точности.
  3. Отбрасываем точки старше последней принятой (часть ОС отдаёт кэш).
  4. Сглаживание: простой фильтр Калмана по широте и долготе, дисперсия измерения равна accuracy², шум процесса зависит от скорости.
  5. В Stationary новая точка пишется, только если отличается от якоря больше чем на max(accuracy, 30 м).
  6. На сервере история прореживается алгоритмом Douglas–Peucker (ε = 10 м) при отдаче маршрута.

Определение движения

Комбинация трёх сигналов: Activity Recognition (Android) и CMMotionActivity (iOS) как основной источник с минимальным расходом; медиана скорости по последним 5 точкам; выход из «стоп-зоны». В MVP на Dart используются скорость и стоп-зона, распознавание активности подключается вместе с нативным модулем 1.1.

Android

  • Foreground service с типом location (обязателен с Android 14) и постоянным уведомлением «Де мої діти: геолокація передається батькам». Уведомление закрепляется в тихом канале с низкой важностью: ненавязчиво, но честно.
  • Разрешения запрашиваются по шагам: ACCESS_FINE_LOCATION, затем отдельным экраном ACCESS_BACKGROUND_LOCATION («Дозволяти завжди»), POST_NOTIFICATIONS, ACTIVITY_RECOGNITION. Для Play Console нужна декларация фоновой геолокации и видео.
  • Doze и App Standby: в Stationary используем Geofencing API (стоп-зона 120 м) — выход из зоны будит приложение и разрешает старт FGS из фона (это исключение из ограничений Android 12+). WorkManager раз в 15 минут работает как сторож, BOOT_COMPLETED перезапускает сервис.
  • Агрессивные прошивки (Xiaomi/MIUI, Samsung, Huawei, Realme, Oppo — массовые в Украине): экран-гайд «Як не дати телефону вимкнути застосунок» по производителю (по данным dontkillmyapp.com) и запрос исключения из оптимизации батареи по явному согласию. Соответствие этого запроса политике Google Play нужно подтвердить на ревью.

iOS

  • Авторизация в два шага: When In Use, затем Always (iOS показывает своё предложение позже). UIBackgroundModes: location, allowsBackgroundLocationUpdates = true, showsBackgroundLocationIndicator = true — синий индикатор честно показывает ребёнку, что геолокация используется.
  • В движении работает CLLocationUpdate.liveUpdates (iOS 17+) или стандартные обновления с activityType = .otherNavigation и pausesLocationUpdatesAutomatically. В Stationary — stopUpdatingLocation плюс significant location change (~500 м) и region monitoring вокруг стоп-точки: оба механизма перезапускают убитое приложение.
  • Лимит 20 регионов на приложение: мониторим стоп-зону и до 19 ближайших геозон.
  • Если пользователь выключил «Точное местоположение», показываем объяснение и запрашиваем временную точность только для SOS.
  • Если пользователь смахнул приложение, iOS не даёт обычных обновлений, их возобновит только significant change. Ребёнку честно показывается подсказка не закрывать приложение, родителю — статус «немає зв'язку».

Offline-очередь

  • SQLite (sqflite): таблица pending_locations с client_id (UUID v4), координатами, временем фикса.
  • Лимит 5 000 точек или 7 дней. При переполнении сначала прореживаются стационарные точки, затем самые старые.
  • Отправка пачками по 100, экспоненциальный backoff с джиттером: 5 с → 10 → 20 … максимум 5 мин. Сброс backoff при смене сети (connectivity_plus) и при выходе приложения на передний план.
  • Сервер идемпотентен (unique(child_id, client_id, recorded_at), ON CONFLICT DO NOTHING), принимает точки до 7 дней назад и не далее 5 минут в будущее. Last location обновляется только для более свежей точки, поэтому досланная старая история не «прыгает» на карте.

10Система геозон

Зоны — круги (центр и радиус 50–2 000 м) с типами Дом, Школа, Спортзал, Другое. Полигоны появятся позже вместе с PostGIS.

  • Где вычисляется: на сервере при приёме каждой пачки, по самой свежей точке ребёнка. Это одна логика для Android и iOS, и не нужно доверять клиенту. Нативные геозоны ОС используются для пробуждения устройства (будет в 1.1).
  • Гистерезис против «дребезга»: вход засчитывается, когда distance + accuracy·0,5 < radius, а выход — когда distance − accuracy·0,5 > radius + max(30 м, 0,15·radius). Точки с accuracy больше радиуса не меняют состояние.
  • Подтверждение: выход фиксируется только при двух точках подряд снаружи или одной с accuracy < 30 м. Это убирает ложные выходы из школы из-за отражений сигнала.
  • Хранение: geofence_states — текущее состояние, обновляется атомарно (UPDATE … WHERE inside IS DISTINCT FROM $new RETURNING), так что при параллельных pod-ах событие создаётся ровно один раз.
  • Уведомления: «Олена прийшла до зони Школа · 08:12», «Олена вийшла із зони Дім · 07:45». Тихие часы для геозон настраиваются, SOS их игнорирует.
  • При создании зоны начальное состояние вычисляется сразу, чтобы первая точка не дала ложный «вход».

11Аутентификация и авторизация

Токены

  • Access token: JWT (EdDSA или HS512 в MVP), TTL 15 минут, claims sub, role, did (device id), jti.
  • Refresh token: 256-битный случайный opaque-токен, в БД хранится только SHA-256-хэш. TTL 60 дней для родителя и 180 дней для ребёнка (ребёнок не должен «выпадать»). Ротация при каждом использовании: если старый токен из той же цепочки предъявлен повторно, вся цепочка отзывается (детект кражи).
  • Привязка к устройству: каждый refresh-токен принадлежит строке devices. Отзыв устройства отзывает его токены и сразу закрывает его WebSocket. Каждый запрос проверяет, что did не отозван (кэш в Redis на 60 с).
  • На устройстве токены хранятся в Keychain / Android Keystore (flutter_secure_storage). На этапе 1.1 добавляется ключевая пара устройства в Secure Enclave/StrongBox и подпись refresh-запросов (proof of possession, по аналогии с DPoP).

12Модель безопасности и правовые требования

Транспорт и данные

  • TLS 1.3 (минимум 1.2), HSTS, certificate pinning в приложениях (SPKI-хэш двух ключей, основной и резервный).
  • Координаты в истории и в SOS шифруются AES-256-GCM на уровне приложения. Ключ данных хранится в KMS (AWS KMS / GCP KMS / HashiCorp Vault), в MVP — в переменной окружения, есть версия ключа и ротация. Дамп базы без ключа бесполезен.
  • Пароли — argon2id (m=19 MiB, t=2, p=1 по рекомендации OWASP).
  • Секреты только в env / secret manager, в репозитории есть .env.example.

End-to-end шифрование: честная оценка

Полное E2E (ребёнок шифрует координаты публичными ключами родителей, сервер видит только шифротекст) сильнее защищает от утечки на сервере, но ломает серверные геозоны, push с адресом и восстановление доступа при потере телефона родителя. Решение:

  • MVP: TLS + шифрование на уровне приложения + строгая модель доступа + короткое хранение. Это уровень Life360/Findmykids, но с шифрованием истории.
  • Версия 2.0 — «Приватний режим» (Premium): семейный ключ X25519, распределяемый между устройствами семьи (по образцу MLS / Signal sender keys), геозоны вычисляются на устройстве ребёнка, а сервер получает только факт «вход в зону #3» и шифротекст координат. SOS-уведомление при этом содержит только «SOS», а координаты расшифровываются на телефоне родителя.

Защита API

  • Rate limiting: глобально по IP, по пользователю, отдельные жёсткие лимиты на /auth/* и /invites/redeem (Redis).
  • Валидация всех DTO (class-validator, whitelist + forbidNonWhitelisted), лимит размера тела 256 КБ, helmet, CORS закрыт (мобильный клиент).
  • Защита от IDOR (см. модель доступа), UUID вместо последовательных ID.
  • Аудит-лог: вход, refresh-reuse, создание/использование приглашений, отзыв устройств, экспорт, удаление, просмотр истории, SOS. Координаты в аудит-лог не пишутся.
  • Антиабьюз: приглашение ребёнка всегда видно ребёнку, нельзя подключить телефон взрослого «тайно». Ребёнок 14+ (и любой пользователь детского приложения) может выйти из семьи, и родители об этом узнают. Это защищает от использования продукта для слежки за партнёром.
  • Плановое: Play Integrity / App Attest для детского приложения, внешний пентест перед публичным запуском.

Законодательство: Украина

  • Закон Украины «О защите персональных данных» №2297-VI. Нужны правовое основание (согласие или договор), уведомление субъекта о целях, сроках и правах, минимизация. Надзорный орган — Уполномоченный Верховной Рады по правам человека.
  • Данные особого риска. Типовой порядок обработки ПД (приказ Омбудсмана №1/02-14) относит данные о местонахождении и путях перемещения лица к обработке, представляющей особый риск. Это означает уведомление Уполномоченного о такой обработке и назначение ответственного лица или подразделения по защите ПД. Точные формулировки и процедуру уведомления нужно проверить с украинским юристом до запуска.
  • Дети. По Гражданскому кодексу за ребёнка до 14 лет действуют родители (законные представители), они и дают согласие. Ребёнок 14–18 лет имеет неполную дееспособность, поэтому мы спрашиваем его собственное согласие в детском приложении в дополнение к согласию родителя. Также учитываем ст. 16 Конвенции ООН о правах ребёнка (право на частную жизнь).
  • Законопроект №8153 о новом законе о защите ПД, приближенном к GDPR, находится на рассмотрении. Проектирование сразу под GDPR снимает риск переделок.
  • Язык: обслуживание потребителей на государственном языке, интерфейс на украинском по умолчанию.
  • Санкции: никаких российских SDK, сервисов и облаков.
  • Военное время: история перемещений может иметь разведывательную ценность. Поэтому короткое хранение, шифрование, отказ от публичных ссылок на маршрут, хостинг вне досягаемости агрессора.

GDPR

GDPR применим, если компания в ЕС или если продукт ориентирован на людей в ЕС (ст. 3(2)). Для украинских семей, где дети живут в Польше, Германии или Чехии, это так.

  • Основание: согласие родителя (ст. 6(1)(a), ст. 8 — возраст цифрового согласия от 13 до 16 лет в зависимости от страны). Договор (ст. 6(1)(b)) — для аккаунта родителя.

  • Privacy by design and default (ст. 25): минимальные сроки, история выключается, пауза доступна.
  • Права субъекта: доступ и экспорт (GET /me/export), удаление (DELETE /me), исправление, отзыв согласия (выход из семьи).
  • Договоры обработки данных (DPA) с облаком, FCM и SMS-провайдером; хранение в ЕС; SCC для передачи в США (Firebase).
  • Уведомление об инциденте в течение 72 часов: процесс в runbook.
  • Политика конфиденциальности, понятная ребёнку: отдельный короткий текст на детском экране.

  • Изменения настроек требуют сети (MVP), с понятной ошибкой

  • онлайн контакт ≤ 5 мин (WS-соединение или точка)
  • недавно контакт ≤ 60 мин
  • немає зв'язку > 60 мин; показываем последнюю точку и время
  • В Stationary heartbeat раз в 15 мин держит статус «онлайн/недавно»

—Сценарий SOS

sequenceDiagram
  participant C as Ребёнок
  participant S as Сервер
  participant P as Родители
  C->>C: удержание 3 с (кольцо + вибро) → отсчёт 5 с с «Скасувати»
  C->>C: Burst-режим трекинга, свежий фикс (≤ 10 с)
  C->>S: POST /v1/sos {clientId, lat, lng, accuracy, battery}
  S->>S: sos_events, шифрование координат, аудит
  S-->>P: WS sos.raised + push critical (каждому родителю)
  P->>S: POST /sos/:id/ack «Бачу, телефоную»
  S-->>C: WS sos.updated → «Мама бачить твій сигнал»
  Note over C,S: нет ответа сервера 15 с → SMS-композер с координатами
  Note over S,P: нет ack 60 с → повтор push
  • Защита от случайного нажатия: удержание 3 секунды с видимым прогрессом, затем 5 секунд отсчёта с большой кнопкой отмены. Отмена после отправки (/sos/:id/cancel) отправляет родителям «Помилкова тривога, все гаразд». Кнопку нельзя нажать в кармане: требуется разблокированный экран.
  • Что получает родитель: полноэкранная тревога с громким звуком, имя и аватар, карта с точкой, время, точность, батарея, маршрут за последние 30 минут, кнопки «Подзвонити», «Бачу», «Маршрут», «Викликати 112».
  • Ребёнок в SOS: трекинг каждые 5–10 с в течение 15 минут, отправка немедленно.
  • Экстренные службы Украины: 112 (единый номер), 101 (ДСНС), 102 (полиция), 103 (скорая), 104 (газ). Публичного API для приёма вызовов от приложений у этих служб нет. Корректная интеграция возможна только как звонок через системный dialer (tel:112) после явного подтверждения пользователя («Зателефонувати 112? Так / Ні»). При звонке с телефона ОС сама может передать координаты через AML (Advanced Mobile Location), если служба его поддерживает; поддержку AML в украинской системе 112 нужно уточнить в МВД/ДСНС. Никакого автоматического звонка.
  • Будущее: партнёрство с охранными компаниями (группы быстрого реагирования) по договору с явным согласием семьи.

20Ключевой код MVP

Код пишется поэтапно в репозиторий de-moi-dity/ (backend/ на NestJS + TypeScript, mobile/ на Flutter). Для каждого этапа есть README с командами запуска и проверки. Ключевые файлы:

  • backend/src/modules/auth/auth.service.ts — ротация refresh-токенов с детектом повторного использования
  • backend/src/modules/invites/invites.service.ts — коды приглашений, HMAC, защита от перебора
  • backend/src/modules/locations/locations.service.ts — идемпотентный batch-ingest, шифрование, last location, presence
  • backend/src/modules/geofences/geofence-engine.ts — переходы с гистерезисом
  • backend/src/modules/sos/sos.service.ts и notifications/ — тревога и push
  • mobile/lib/location/tracking_policy.dart — адаптивная частота по движению и батарее
  • mobile/lib/location/location_filter.dart — фильтрация шума и Калман
  • mobile/lib/location/location_queue.dart, sync_service.dart — offline-очередь и досылка с backoff
